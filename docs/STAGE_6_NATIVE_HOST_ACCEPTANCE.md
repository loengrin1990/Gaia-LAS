# Ручная приёмка нативного окна Gaia

Соберите приложение командой:

```bash
zsh scripts/build_macos_host.sh
```

Готовое приложение появится в `native/macos/build/DerivedData/Build/Products/Debug/Gaia.app`. Для dev-сборки без зашитых путей при необходимости задайте `GAIA_REPOSITORY_ROOT` и `GAIA_PYTHON` в окружении Finder/запуска.

1. Откройте `Gaia.app` двойным кликом или `open`.
2. Убедитесь, что загружен интерфейс Gaia.
3. Нажмите «Выбрать материалы» и отмените системную панель.
4. Откройте панель повторно.
5. Выберите один нейтральный синтетический файл и убедитесь, что он появился в обычном потоке добавления.
6. Выберите несколько синтетических файлов: текущий input поддерживает multiple.
7. Убедитесь, что ни один материал не зарегистрирован дважды.
8. Закройте Gaia и убедитесь, что не остался Python-процесс, запущенный этим окном.
9. При необходимости включите `GAIA_NATIVE_HOST_DIAGNOSTICS=1` и путь JSONL: убедитесь, что там есть только коды событий, порт, счётчики и безопасные статусы — без имён и путей файлов.

В повторной проверке после 6.3b выбор одного нейтрального синтетического файла должен сразу запустить обычное добавление, без отдельного нажатия кнопки. Проверьте, что материал появляется ровно один раз; затем повторите выбор того же файла и отмену после успешного выбора.

Если нужно отделить WebKit от основного UI, запустите `zsh scripts/file_picker_harness.sh`. Он открывает один synthetic input через тот же `WKWebView` и `WKUIDelegate`; после ручного выбора JSONL должен содержать `selected_url_count: 1`, `completion_call_count: 1` и page `file_count: 1`. Этот harness не читает содержимое файла и не отправляет его на backend.

Текущая HTML-реализация не содержит собственного обработчика drag-and-drop, поэтому этот сценарий не включён в приёмку и не заявляется как пройденный. Host не читает dropped files и не добавляет альтернативную загрузку; добавление drag-and-drop требует отдельного согласованного UI-шага.

Эта ручная приёмка намеренно не выполнена автоматически и остаётся обязательной перед признанием этапа 6 завершённым.

До ручной проверки выполнен автоматический launch-smoke: он подтверждает ранние lifecycle events и загрузку synthetic loopback Gaia. Он не заменяет проверку видимости окна и `NSOpenPanel` пользователем.

## Результат ручной приёмки 2026-07-27

Ручная приёмка пройдена на синтетическом файле: `Gaia.app` показало интерфейс, системная панель открылась, отмена и повторный выбор не вызвали падения, выбранный файл попал в существующий upload-flow ровно один раз. Повторный выбор того же файла и отмена после успешного выбора также работают. При закрытии host завершается только owned backend и освобождается его порт.

Native host не читает содержимое файла и не создаёт второй upload-flow. JXA больше не является основным путём и остаётся временным fallback. Drag-and-drop в текущем web UI не реализован и должен рассматриваться как отдельная будущая UI-доработка. Этап 6 остаётся частично принятым: отдельный незакрытый блокер — Veil.

## Приёмка исправления Veil

Native host в этот срез не входит и его подтверждённый результат выше не пересматривается. Для закрытия Veil вручную выполните три сценария только на синтетическом рабочем пространстве: полный успешный ответ без находок показывает «Проверка завершена: дополнительных сведений не найдено» и не подтверждает материал сам; полный успешный ответ с находкой показывает «Найдены сведения, требующие проверки» и ведёт в существующий поток решений; пустой или некорректный ответ показывает «Автоматическая проверка не завершена. Проверьте очищенный текст вручную», не объявляет текст чистым и оставляет доступными повторную проверку и отдельное ручное подтверждение. После ручного подтверждения последующий анализ становится доступен, но это не считается подтверждённым результатом Veil.

Для приёмки можно подменить локальный ответ test double: вернуть полный объект с завершённым статусом и пустым списком, такой же объект с одной корректной синтетической находкой либо пустую строку/некорректный объект. Для ручной ветви после подтверждения обязательно нажмите «Собрать проектный контекст» и убедитесь, что кандидаты появились; повторное подтверждение не должно создать новую обработку. Не используйте рабочие материалы, не сохраняйте сырые ответы модели и не включайте содержимое очищенного текста в журнал.

Повторная ручная приёмка compiler выполняется в новом synthetic workspace: добавьте пять явных утверждений (решение, требование, риск, действие и открытый вопрос), завершите проверку и подтвердите материал, затем нажмите «Собрать проектный контекст». Должны появиться пять типов кандидатов, каждый с действиями «Подтвердить», «Уточнить» и «Отклонить»; повторный запуск до решений не создаёт дубликаты. При невалидном ответе интерфейс показывает безопасный код `CONTEXT_*`, не JSON и не содержимое материала.
