# Gaia — отмена запроса и design review доверия

Жанр: engineering_review. Authority: operational. Baseline `9468dc60154bb09c3dea008d4a1b56e715840f15`, ветка `codex/cancel-compute-slot`, изолированный worktree `Gaia/tmp/cancel-slot-pilot`. Это corrective feature slice, не stable/MVP и не новая архитектура памяти. Ни повторного holdout, ни prompt tuning, ни новой модели не запускали. Review инженерный, не внешняя пользовательская приёмка.

## Подтверждённая кодовая проблема

Детерминированный тест с двумя проходами и блокируемым fake local_operations показал: в baseline cancel меняет job.state на cancelled, после чего any(state == running) больше не видит выполняющийся запрос. Второй analyze допускается, пока первый fake запрос ещё заблокирован. Red результат: 1 test, 1 failure, `AddressedMemoryError not raised`. Принятая память при этом защищена прежними status/version gates, но сериализация вычислений нарушается.

Это реалистичный путь к дополнительной нагрузке. **Не доказано, что именно он вызвал прежний GPU OOM**: другие модельные процессы и давление памяти остаются самостоятельными факторами. Отсутствие semantic guarantee после 3/6 model FAIL — другая проблема и этим исправлением не устраняется.

## Минимальное решение и граница

- Отдельный in-process owner вычислительного слота под существующим desk.lock. Он резервируется перед запуском worker и снимается в finally после завершения локального вызова/обработки результата, независимо от cancelled/failed/done статуса прохода. Ошибка создания/старта потока также снимает резерв. Очередь не добавляется.
- Cancel сразу закрывает возможность stage/accept позднего результата; слот не освобождает. Отмена до фактического старта worker не вызывает модель, но резерв удерживается, пока worker не обработает закрытый статус. Повторная отмена уже закрытого прохода безопасно отклоняется и не освобождает слот.
- overview/job возвращают additive analysis_busy; поле не сохраняется на диск и не требует миграции. Поздний ответ/exception не перезаписывает cancelled. Только после release новый analyze допускается, включая fast no-change проход.
- UI отдельно подтверждает отмену и показывает занятость локального запроса. Отмену нельзя читать как «GPU освобождён». Следующий анализ блокируется; исходная и восстановленная страницы замечают release через bounded polling существующего локального API. После штатного быстрого завершения индикатор тоже меняется на завершённый запрос. Источники/выбор/preview/confirm не меняются.
- Слот относится только к одному AddressedMemoryPilot в одном backend. Это не межпроектная/межпроцессная блокировка и не глобальный GPU quota. После HTTP timeout вычисление внутри Ollama может продолжаться; завершение Python-запроса не является доказанным physical abort. Уже существующий single-writer-per-store предел остаётся обязательным.

## Что проверено

Fake-only tests: удержание слота при cancel с поздним proposal и exception; cancel-before-start без вызова модели; repeated cancel; нормальный proposal/no-changes; model/proposal exceptions; thread constructor/start failures; успешный следующий запрос после release. Все workers в детерминированных тестах явно joined, реальные модели не вызываются.

В отдельном UI fixture на 8799 инженер отменил заблокированный fake запрос, подготовил другой проход и увидел disabled Analyze при неизменной памяти. После test-only освобождения первый late result не появился, новый анализ автоматически стал доступен и создал только draft. На окончательном UI отдельно видны «Проход отменён» и «Локальный запрос ещё выполняется»; штатное завершение возвращает свободный слот без ложного «ещё выполняется». Это проверка функционального lifecycle, не model quality или user study.

Personal-trial backend 8796, его store и исходный worktree `tmp/addressed-memory-pilot` **не изменялись и не перезапускались**. Он продолжает использовать прежнюю 9468dc6 без этого исправления; feature push не обновляет его автоматически. Перед любым разрешённым обновлением живой пробы потребуется отдельное явное действие. Пока там не следует интерпретировать Cancel как разрешение немедленно запустить новый расчёт.

## Design review: чему доверять

| Утверждение | Доказательство / предел доверия |
|---|---|
| Цитата есть в выбранном источнике | Exact quote и frozen provenance дают механическую проверку присутствия/версии. Они не доказывают, что цитата логически подтверждает всю замену, и не делают исходный документ истинным. |
| Предложение корректно и полно | Не доказано: 3/6 model FAIL в frozen holdout включали malformed append, конфликт и подмену постоянного условия событием. operations=[] не доказывает полноту/отсутствие новых сведений. |
| Невыбранный текст сохранится | Детерминированная сборка и preview/selection/version checks поддерживают буквальное сохранение. Если человек выбрал неверную замену, механическая сохранность остального текста не исправляет её смысл. |
| Противоречие заметно | В коротком holdout инженер видел обе текущие цитаты. Если модель не упомянула один источник, один удачный excerpt может скрыть противоречие. Проверять нужно весь выбранный набор, а не только предложенную цитату; полнота поиска по архиву отдельно не доказана. |
| Отмена защищает память и нагрузку | Память — немедленно через закрытый статус; один локальный worker — до finally. Физическое завершение provider/GPU и чужие процессы этим не гарантируются. |

Нагрузка на человека остаётся значимой: выбрать правильные материалы, проверить срок/роль/модальность/условия, просмотреть полный итог и принять subset. Порог «галочки после точной цитаты» создаёт риск ложного доверия. Контекст рядом с цитатой помогает навигации, но не заменяет проверку противоречий и полноты. Повторяющиеся предупреждения и разделение задачи/источников/кнопок на странице могут затруднять новичка; оценка человеком ещё нужна. Дополнительный самостоятельный benefit пилота — принятое состояние, история и контролируемые изменения, а не доказанное превосходство над разовым сильным чатом.

## Альтернативы и приоритеты

| Вариант | Что даёт | Цена / необходимое решение |
|---|---|---|
| Сохранить review-first pilot | Уже принятый контракт, обратимость, subset/preview/confirm. Сейчас разумен только для личной synthetic пробы с ручной проверкой. | Высокая нагрузка и риск ошибки review. Не объявлять автоматическую достоверность; следующий источник evidence — feedback Ильи. |
| Evidence-first extraction как отдельный design | Возможное выделение атомарных claims с source spans и явными «обязанность / событие / предложение», затем сопоставление/конфликты. | Это не перестановка JSON-полей (она уже не помогла). Нужны отдельные contract/scope и критерии полноты/сохранения/ошибок; здесь не реализуется. Не гарантирует истинность источника. |
| Более сильная модель — отдельное сравнение | Может улучшить reasoning; измеряется отдельно на frozen/новом holdout без подгонки. | Не runtime migration и не автоматическая замена. Сохраняются privacy и manual-copy ограничения, внешние API не добавляются; для локальной модели нужна ресурсная квалификация. Модель не исправляет lifecycle bug приложения. |

P0 этого slice — подтверждённая сериализация и правдивые состояния cancel/compute, regression/cleanup. P1 — личный feedback Ильи о полезности и цене review, без повторения такого же автоматического batch. P2 — отдельный выбор evidence-first/typed design либо сравнительной оценки модели только по результатам feedback и явному scope. Normative contracts, модельный prompt и accepted memory schema не менялись. Merge/deploy/force-push не выполняются.

При автоматической проверке слота обновляются только статус и доступность анализа; review-карточки не перестраиваются, поэтому несохранённая правка/выбор не теряются от status polling. Отдельная UI-регрессия проверяет сохранение того же редактора и текста. Это часть безопасного review, а не новый workflow данных.

Финальные evidence/checks: отдельная двухпоточная probe на сохранённом baseline измерила peak=2 одновременно вошедших fake requests до release первого; на исправлении peak=1, второй отклонён, принятая версия в обоих случаях 0. Targeted addressed suite: **32 tests, 0 failures/errors/skips** (4.732 s); full offline: **595 tests, 0 failures/errors/skips** (19.123 s); UI: **10 tests, 0 failures/skips/cancelled**, обе прежние JS check-программы проходят. Syntax/static/diff/credential scan и documentation-governance sync (28 документов) успешны. Launcher-only socket guard запрещал 8796/модельные порты и внешние соединения; зафиксировано 0 попыток обращения к ним. Guard и сырые логи не входят в Git.

Pre-edit GitNexus CLI (MCP не подключён) дал LOW по целевым методам/reload; динамическая таблица dispatch прочитана вручную, поскольку граф не разворачивает все её runtime callers. Расширенный orchestration review охватил HTTP dispatch → analyze/cancel/job/overview → worker/propose/finally, accepted-memory/source/version границы и оба UI polling paths. Post-edit staged scope: HIGH, 7 files / 36 symbols / 6 flows; compare main: CRITICAL, 26 files / 300 symbols / 26 flows, включает прежнюю линию. Предупреждение сообщено, changed flows проверены: они ограничены analyze/run. Privacy, accepted storage, внешние маршруты и модельный payload не менялись. Старый personal-trial worktree clean на 9468dc6, PID 26097 сохранён; пять dirty-файлов quote-slice совпадают с прежними hashes. Нет merge/deploy/force-push. Commit/remote SHA и safe snapshot фиксируются после публикации в MemoryHub отдельно от старой живой пробы.
