## Подтверждённый продуктовый дефект и минимальная правка

Job и статус повторного открытия материала считали только legacy candidates/receipt count. Корректное grounded OC-предложение могло уже находиться в «Требует решения», пока экран сообщал, что контекст не найден; OC-панель после job не перечитывалась.

Общая content-free проекция результата в существующем compiler-модуле используется job и HTTP status: учитывает `bridge_accepted` из имеющейся диагностики, неизвестное отличается от нуля. Legacy result list, receipt schema, routing/persistence, provenance/quotes, authority, sensitivity и ручное подтверждение не меняются. После завершения обновляются обе существующие очереди, с защитой от устаревшего чтения при смене проекта/перекрытии запросов. Настоящий пустой ответ подписан как отсутствие предложений модели, а не доказанное отсутствие фактов в материале. Подробности — в canonical [reliability](../CONTEXT_COMPILER_RELIABILITY.md) и [UI](../USER_INTERFACE.md).

GitNexus pre-edit: job/poll LOW, callback-связи частично динамические и проверены вручную; inline `loadOperationalContextReview` HIGH (16 impacted, 1 flow), предупреждение дано до изменения. Поэтому regression включает main HTTP, повтор/receipt, историческую совместимость и поздние ответы других/того же проекта. Inline HTML анализируется через точную projection реально rendered scripts, source SHA/lines сохранены локально. Никакого обхода gate.

## UI и ограничения человеческой проверки

На окончательном основном UI в отдельном disposable профиле выполнен offline replay того же настоящего ответа. Видны исходный очищенный абзац, успешное завершение, тот же успешный статус при повторном открытии и повторной сборке, одно предложение в «Требует решения», пустой текущий подтверждённый OC. Повтор использует receipt, не делает новый model call и не создаёт дубль. Временный UI остановлен, профиль удалён. Это инженерная симуляция review; полный live-model browser upload и независимая личная проба не выполнялись.

Остаётся продуктовый долг: OC-карточка показывает общую подпись локального источника, без inline цитаты/перехода к точному основанию. В этой короткой пробе источник можно сверить, вернувшись к материалу, но это дополнительная нагрузка. Автоматической семантической гарантии нет; неоднозначности и добавленные предположения человек должен исключать сам. Также legacy summary/search и OC остаются разными принятыми потоками; этот slice не меняет их архитектуру.

Следующий конкретный шаг: личная проба review-first на искусственном проекте; если требуется следующий implementation slice — безопасное открытие точного очищенного основания из OC-карточки через существующую provenance-цепочку, после отдельного узкого scope/gate. Не нужны новые одинаковые holdout или tuning по этой выборке. Безопасный повтор основного пути без генераций — [E2E runbook](../E2E_VALIDATION.md#повторяемая-проверка-основного-пути-без-модели). Диагностический `scripts/qualify_core_local_holdout.py --run-local` требует явного решения повторить batch, уже работающего собственного local server и не перезаписывает сохранённый результат; обычный smoke его не запускает.
