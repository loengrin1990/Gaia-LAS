## Точный фрагмент: остановленная архитектурная часть

[Нормативный OC v0](../OPERATIONAL_CONTEXT_V0.md) и [Store contract](../OPERATIONAL_CONTEXT_STORE.md) оставляют в `SafeProvenance` только opaque `source_ref`, `candidate_ref`, optional `memory_ref`; quotes/произвольных metadata там нет. Модель/парсер знают проверенные offsets в момент extraction, но OC bridge сохраняет hash identity и ссылку на sanitized version, а не record с фрагментом. Content-free compiler receipt предназначен для диагностики, а не хранения цитат. Поэтому существующие данные не позволяют честно объявить точный фрагмент сохранённым.

В этом slice не добавлены новые поля/sidecar/evidence storage и не закодированы offsets в opaque ID. Не выполняется поиск похожей цитаты, реконструкция по хешу или миграция. И прежние, и новые карточки сохраняют честное `whole_material` поведение. Предпочтительный способ хранения **не выбран за архитектора**. Конкретная развилка для следующего решения: отдельный нормативно определённый immutable evidence-record с source-version/checksum, span и проверкой связи с candidate либо версионированное typed расширение provenance со span/checksum. Нужны canonical home, retention/privacy, identity/confirmation binding и совместимость старых записей. Ни один вариант автоматически не принят.

## Разрешённый независимый fallback и минимальная правка

На [трёх новых естественных синтетических материалах](../../tests/fixtures/oc_conflict_review_20261117.json) проверены факт, конфликт дат и недостаток основания. Предложения составлены вручную для проверки приложения, не получены от модели. В baseline comparison-card показывал «Было / Стало» и знал `replacement_of`, но кнопка открывала только основание нового предложения: прежний источник приходилось искать в другом списке. Отсутствие двух различимых действий сначала воспроизведено тестом (8 исходных checks PASS, новый FAIL), затем исправлено без изменения backend.

Теперь replacement-card имеет «Открыть основание предложения» (`pending/<candidate>`) и «Открыть основание прежнего факта» (`current/<replacement_of>`). Используются прежние exact scoped read-only API, viewer, confirmation и no-store/privacy gates; отсутствие prior pointer не создаёт фиктивной ссылки. Stale prior ID безопасно отклоняется: текущий похожий item/новый source вместо него не подставляется. Текст и факт не принимаются чтением. Ordinary/current карточки сохраняют прежнюю кнопку.

Для повторения добавлен opt-in `--serve --oc-conflict` к существующему core smoke, с выключенными моделями и одним временным synthetic-профилем. Не создан отдельный demo-сервис/формат, не расширен Tristan; модельных/платных/внешних вызовов0. [Сценарий личной пробы](../E2E_VALIDATION.md#проверка-двух-оснований-при-замене-oc).

Human-readable надписи проверены. Собственный UI остановлен, временный профиль удалён. Native window/file picker не проверялись. Это инженерная симуляция review, не независимое исследование и не model-quality оценка.

Практическая польза: обе стороны конфликта доступны из одной карточки. Цена review остаётся: два документа открываются последовательно; полный материал не является точной цитатой, source availability не означает entailment/полноту, а разрешение конфликта остаётся за человеком. Историческое подтверждение в журнале не означает current authority: заменённый item отдельно имеет lifecycle history. Исторические/source-only/Memory/raw источники не получили новых прав доступа.
