# Надёжная сборка проектного контекста

## Причина и исправление

Прежний `CONTEXT_JSON_PARSE` возникал при попытке извлечь весь подтверждённый материал одним запросом: вход мог быть сокращён общим слоем prompt, а выходной JSON — оборван лимитом генерации. Это разные ограничения: окно контекста ограничивает объём запроса вместе с инструкциями, а `num_predict` — объём ответа.

Теперь Gaia никогда не передаёт длинный материал одним запросом. Детерминированный splitter выделяет заголовки, абзацы и пункты; длинные абзацы делит по предложениям, а затем безопасно по символам. Каждый фрагмент имеет глобальные `start`/`end`; локальные координаты модели переводятся в координаты полного очищенного текста.

## Профиль и пределы

Маршрут `context_compiler` задаётся отдельно: `prompt_char_limit=9000`, `context_length=32768`, `max_tokens=2400`, `temperature=0`, timeout вызова 120 секунд, фрагмент до 4000 символов/12 смысловых единиц, overlap 250 символов и не более 80 фрагментов. Для текущего Mac локально выбран `qwen3.5:9b`. Gaia передаёт `num_ctx` и `num_predict` в каждом запросе Ollama, не изменяя глобальную настройку Ollama.

Ручной fallback — `gpt-oss:20b` с `context_length=16384`, `max_tokens=2400` и только последовательной работой. Автоматического переключения модели нет; 26B/27B модели Gaia не загружает.

Материал более `max_input_chars` или с числом фрагментов сверх лимита не обрезается: пользователю предлагается разделить его по главам. Это исключает частичный контекст.

## Структурированный результат и восстановление

Для Ollama поле `format` получает JSON Schema: только объект с `candidates`, до 16 кандидатов, с закрытыми полями и обязательными type/title/statement/block/confidence/requires_review. Строгая backend-проверка остаётся второй линией защиты. OpenAI-compatible маршруты сохраняют прежний совместимый путь.

Безопасные показатели различают пустой ответ, обрезанный вывод, JSON parse, нарушения схемы, timeout и недоступность provider. Ни prompt, ни raw-ответ, ни текст фрагмента в диагностику или receipt не записываются.

При ошибке JSON/schema или достижении потолка кандидатов Gaia делает один retry. При повторной ошибке фрагмент делится на две ближайшие структурные части и обрабатывается последовательно. Если минимальный фрагмент не удаётся обработать, завершается вся job без записи кандидатов.

Необязательные метаданные (`actor_ref`, `deadline`, `status`, `priority`, `reason`, `consequence`, `relations`) допускаются схемой только как дополнение к шести обязательным полям. Модель обязана включать их лишь при прямом упоминании во фрагменте; Gaia не выводит их из предположений.

## Атомарность, receipt и job

Все вызовы модели, проверка, дедупликация по `(type, нормализованный statement)` и объединение global `block_links` происходят в памяти. Запись в provenance registry выполняется одним атомарным обновлением только после успеха всех фрагментов. Receipt содержит только версии, route/model, timestamp, количество фрагментов, кандидатов и итоговые IDs. Повторная успешная сборка возвращает receipt-набор и не вызывает модель повторно.

Receipt дополнительно связывает workspace и sanitized artifact. При повторе Gaia восстанавливает элементы строго по сохранённым context IDs и проверяет их доступность и тип; повреждённый receipt возвращает контролируемую ошибку, а не пустой результат.

`POST /api/context/<artifact>/compile` возвращает `202`, `job_id` и `status_url`. Job последовательно исполняет фрагменты, показывает прогресс и допускает отмену через общий endpoint job. Отмена до persistence оставляет данные без изменений. UI проверяет generation и workspace при каждом ответе: поздний результат прошлого рабочего пространства не отрисовывается.

## Ручная приёмка

1. Перезапустите Ollama и Gaia, проверьте `context_compiler` в local status.
2. В двух новых рабочих пространствах добавьте чистые синтетические `Gaia_Stage7_Орбита.txt` и `Gaia_Stage7_Север.txt`, подтвердите очищенные версии.
3. Запустите сборку: должен отображаться прогресс «фрагмент X из Y» и кандидаты пяти типов без `CONTEXT_JSON_PARSE`.
4. Запустите сборку повторно: модель не должна вызываться заново.
5. На отдельном длинном синтетическом материале отмените job и убедитесь, что кандидаты не появились.
6. Переключите рабочее пространство во время job: прежние кандидаты, технические IDs, prompt и raw JSON не должны появиться в интерфейсе.

Stage 7 не считается принятой до независимого review и ручной проверки.
