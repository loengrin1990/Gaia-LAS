# Компилятор проектного контекста

## Назначение и граница

Этап 4 преобразует только актуальное, подтверждённое и очищенное представление материала в кандидаты проектного контекста. Путь работы: подтверждённое очищенное представление → локальный компилятор → кандидаты → решение пользователя → подтверждённая сводка проекта.

Компилятор не читает исходный файл, извлечение, технические журналы, таблицы псевдонимов и данные другого рабочего пространства. Он использует действующий локальный loopback-маршрут модели; облачные и внешние вызовы не добавлены.

Для компилятора выделен отдельный локальный маршрут `context_compiler`, а не маршрут проверки маскирования. Production contract: `ollama_qwen3_14b` / `qwen3:14b` через Ollama `/api/chat`, `think=false`, `num_ctx=16384`, temperature 0 и полный JSON Schema. Его provider, `num_ctx`, output limit, timeout и параметры фрагментов задаются в `config.json` отдельно от provider по умолчанию. Длинный материал разделяется до вызова модели; ответ Ollama запрашивается по JSON Schema, а точная цитата переводится в глобальные координаты локально. Ошибки JSON/schema получают один retry. Все кандидаты записываются только после успешной проверки всех частей; receipt делает повторный compile идемпотентным. Local override обязан сохранять этот contract. Подробный контракт и ручная приёмка: [CONTEXT_COMPILER_RELIABILITY.md](CONTEXT_COMPILER_RELIABILITY.md).

Маршруту даётся достаточный локальный срок на структурированный ответ. Запрос явно задаёт единственную допустимую JSON-схему с точной непустой `evidence_quote`; Gaia сама вычисляет координаты блока. Неверный ответ по-прежнему отклоняется без частичного сохранения.

## Контракт модели

Модель получает только очищенный текст и возвращает один JSON-объект с единственным полем `candidates`, без Markdown и сопроводительного текста. Разрешены пять типов: `requirement`, `decision`, `risk`, `open_question` и `action`; русское «Решение» обязано стать `decision`, а `solution` не допускается. У каждого кандидата есть непустой заголовок до 160 символов, непустое содержание до 1200 символов, точная непустая `evidence_quote`, строковый уровень уверенности `low`, `medium` или `high` и обязательный JSON-признак `requires_review: true` именно с подчёркиванием.

Допустимы только явно извлечённые необязательные поля: ответственный, срок, статус, приоритет, причина и последствие, а также предложенные связи с другими кандидатами. Отсутствующее поле не заменяется предположением. Явно указанный в материале статус хранится отдельно от состояния пользовательской проверки и не может его подменить. Валидатор отклоняет неизвестные поля и типы, неверные координаты, слишком длинный или большой ответ и любое частичное сохранение недействительного ответа. Ошибка модели оставляет очищенный материал и прежний подтверждённый контекст без изменений; в технический журнал не записываются текст кандидатов и полный ответ модели.

Если ответ пуст, не является JSON, содержит неверный верхний объект, неизвестный тип, неверное поле или координаты, весь результат отклоняется до первой записи. Частично верные кандидаты не сохраняются и не подменяются пустым списком. Нормализация не угадывает смысл: неизвестные enum, `solution`, числовая уверенность и ключ с пробелом остаются ошибкой контракта.

## Хранение, происхождение и версии

Кандидаты хранятся в существующей зоне `context` реестра происхождения. Для записи сохраняются безопасные идентификаторы рабочего пространства и подтверждённого очищенного представления, ссылка на блок, версия компилятора и схемы запроса, локальный маршрут, версия кандидата, связь с заменённой версией и решения пользователя. Содержимое остаётся только очищенным; исходный текст не возвращается происхождением.

Подтверждение относится к конкретной версии. Редактирование создаёт новую версию, а не перезаписывает подтверждённый элемент. Повторный запуск с тем же очищенным представлением и версией компилятора идемпотентен. Изменение представления или версии компилятора создаёт новые кандидаты и не меняет старый подтверждённый контекст автоматически.

## Повторы и противоречия

Точный нормализованный повтор одного типа не создаёт копию: к существующему элементу добавляется ссылка на новый подтверждённый источник. Похожие элементы остаются отдельными и связанными для проверки. Противоречащие решения также остаются отдельными: новый кандидат получает состояние «Есть противоречие», а прежнее подтверждённое решение остаётся действующим до явного выбора пользователя.

Пользователь может подтвердить, уточнить или отклонить кандидат, отметить его повтором другого элемента, оставить противоречие открытым, выбрать актуальный вариант или сохранить оба варианта. Эти действия доступны только внутри того же рабочего пространства.

## Сводка и API

Сводка состоит только из актуальных подтверждённых требований, решений, рисков, открытых вопросов и действий. Она показывает понятное содержание, явно указанного ответственного и срок, количество источников, наличие связи и дату изменения. Доступны фильтры по типу, статусу, наличию противоречия, срока и ответственного. Неподтверждённые, отклонённые и заменённые версии не включаются.

Локальный API позволяет запустить компиляцию, узнать её статус, получить кандидаты и безопасное происхождение, принять решение по кандидату, отметить повтор, решить конфликт и получить сводку. Он проверяет рабочее пространство и не выдаёт исходные материалы, таблицы псевдонимов или необработанный ответ модели.

Для кандидата, построенного из RPM PDF, `GET /api/context/<идентификатор>/evidence?project=…` возвращает только безопасные ссылки на supporting fragments: modality, страницу, локатор, origin и способ подтверждения связи. Исходный текст, OCR-вывод и само изображение этим API не выдаются.

`GET /api/context/overview?project=…` — отдельный read-only контракт рабочего обзора. Он не запускает модель и не создаёт записи: возвращает только счётчики текущих элементов, подтверждённые типы, безопасные точки внимания, короткие подборки и безопасные роли. Подборки не содержат идентификаторов, ссылок на источники, путей, промптов, ответов модели или исходного текста.

Необязательное поле «Ответственный или роль» допускается только тогда, когда это значение прямо содержится в очищенном фрагменте. Компилятор не восстанавливает имена из исходного материала и не строит сопоставления с псевдонимами. Срок, явный статус и приоритет остаются необязательными, но при наличии сохраняются при уточнении кандидата.

## Ограничения этапа

Этап 4 не добавляет экспорт, полнотекстовый поиск, автоматическое разрешение конфликтов, миграцию данных, внешние сервисы или общую стабилизацию. Эти границы, а также будущий поиск и экспорт, остаются предметом последующих отдельных этапов.

Этап 6 предоставляет этот путь в разделах «Контекст проекта» и «Сводка»; пользовательские формулировки и навигация описаны в [документе интерфейса](USER_INTERFACE.md).
## Этап 7: поиск подтверждённого контекста

Поиск вынесен в `gaia.context_search` и читает только проекцию актуальных подтверждённых элементов. Он не участвует в компиляции, не вызывает локальную модель и не создаёт новые записи. `ContextService.summary()` сохранён для обратной совместимости и теперь включает `item_type` в каждом элементе.
# Локальный профиль извлечения

Для production-профиля используйте только `qwen3:14b` в маршруте `context_compiler`: Ollama `/api/chat`, полный JSON Schema, `think=false`, `num_ctx=16384`, `num_predict=2400`, temperature 0. Остальные маршруты не меняются. Воспроизводимый безопасный smoke: `python3 scripts/smoke_context_compiler.py`; он не выводит prompt, raw response или текст материала и завершится с ошибкой при отсутствии обязательных кандидатов либо metadata действия.

Перед первой генерацией Gaia выполняет пустую локальную загрузку модели. Лимит загрузки (`model_load_timeout_seconds`) и лимит генерации (`model_call_timeout_seconds`) независимы; оба ограничены отдельным process boundary. Во время загрузки экран сообщает, что первый запуск может занять несколько минут, затем показывает номер текущего фрагмента.
