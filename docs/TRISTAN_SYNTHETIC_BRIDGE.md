# Узкий синтетический мост к модели Тристана

Статус: development pilot, отдельная feature-ветка; не подключён к работающей Gaia. Инструменты `scripts.tristan_synthetic`, `scripts.tristan_synthetic_send` и отдельный браузерный `scripts.tristan_synthetic_review` используют существующий `apply_operations`, но не импортируют сервер, настройки, пользовательское хранилище или провайдеры Gaia. Это прямой Responses API к модели DeepSeek V4.1 Flash прежнего эксперимента, **не полный OpenClaw/агент Тристан**.

## Границы

Разрешены только шесть case ID из `tests/fixtures/addressed_memory_holdout.json`, закреплённого SHA-256. Нет параметров для своего проекта, текста, документов, пути к памяти или модели. `acceptance` из fixture не отправляется. Источники, задача и исходная память сверяются с корпусом буквально; неизвестный/изменённый корпус или пакет отклоняется. Известный `conflict` блокируется ещё до создания отправляемой сессии: это явное ограничение данного кейса, не общий детектор противоречий. Прочие смысловые ошибки по-прежнему требует обнаруживать человек.

Каждая сессия создаётся в новом приватном временном каталоге `gaia-tristan-synthetic-*` с единственным синтетическим store. Исходная версия 1 — fixture, не принятая память пользователя. Пакет содержит случайный request_id, base_version, corpus digest, полные выбранные тексты и packet digest. При каждой операции пакет повторно сверяется с корпусом. После принятия версия 2 закрывает проход; продолжение от принятой версии и перенос результата в живую Gaia **не реализованы**.

Ответ обязан сам вернуть ровно `request_id`, `base_version`, `packet_digest`, `operations`. Идентификаторы не дописываются за модель. Принимается только полный `completed` Responses envelope с одним завершённым ответом assistant/output_text. Reasoning, отказ, tools, неполный, лишний/невалидный JSON, неверная привязка, выдуманная цитата, отсутствующий/неоднозначный old_text, пересечения, дубль и превышение размера отклоняются. Валидатор проверяет адреса и буквальные цитаты, **не доказывает семантическую обоснованность**.

Импорт/успешный API-запрос сохраняют только кандидат. Review показывает полные источники, прежний текст и операции без reasoning. Preview выбранных индексов не пишет память. Confirm требует отдельного явного флага и совпадения digest preview, который связывает весь кандидат, выбор, версию, пакет и итог. Подтверждение повторно валидирует состояние под lock; сохраняет только выбранные операции, остальной текст — буквально. Cancel закрывает проход без изменения принятого текста; поздний результат/повторный confirm отклоняются. Во время синхронного платного запроса session/compute lock занят: cancel возвращает `session_busy`, физический abort не обещается. Ответ сам ничего не принимает.

Это разрешённый владельцем эксперимент с закрытыми синтетическими fixture, а не новый production external-runtime или разрешение отправлять `unknown` память. PB-0, handling, masking, export и исключение ручного копирования Gaia не менялись. Переименовать реальные данные в synthetic или заменить fixture без ошибки digest нельзя. Не копируйте реальные данные в эксперимент, ответ модели или receipt.

## Запуск и ручная проверка

Из корня feature checkout, Python 3.9+; установка новых зависимостей не нужна:

```bash
python3 -B -m scripts.tristan_synthetic create partial
python3 -B -m scripts.tristan_synthetic show <выданный-абсолютный-каталог>
python3 -B -m scripts.tristan_synthetic_send <каталог> --benchmark-dir <исходный-benchmark>
```

Третья команда по умолчанию **offline**: показывает точный запрос и предрезерв, не читает ключ и не вызывает API. Исходный benchmark определяется хешем `run.mjs`, оригинальным расположением и хешем его журнала. Повреждение/перенос не открывают новый бюджет. Установленные auth/model/project извлекаются из этого прежнего безопасного маршрута; ключ не выводится и не входит в репозиторий.

Платное действие — отдельный `--send --coverage-receipt <private-json> --confirm-packet-digest <просмотренный-digest>`. Оно требует свежей (не старше 10 минут) ручной проверки действующего гранта и тарифа. Receipt хранить вне Git, поля: `observed_at`/`grant_expires_at` (ISO с timezone), `ai_studio_covered: true`, `personal_funds_allowed: false`, `grant_remaining_rub`, `input_rub_per_1000: 0.3`, `output_rub_per_1000: 0.5`. Это фиксация проверки оператором, не криптографическая аттестация и не серверный grant-only hard cap. Если покрытие/тариф не подтверждены, вызов запрещён.

Runner обращается только к `ai.api.cloud.yandex.net/v1/responses` через TLS, без proxy, redirect, retry, fallback, tools, истории диалога или доступа модели к файлам. `store=false` запрещает сохранение ответа для последующего API retrieval, но не является обещанием отсутствия иных журналов провайдера. Input не обрезается. Output ограничен 4096 токенами вместе с reasoning; размер ответа — 1 MB. Тайм-аут сетевого ожидания — 120 секунд, чтение тела дополнительно проверяет оставшийся wall deadline; это не серверная гарантия остановки вычисления.

После полного ответа:

```bash
python3 -B -m scripts.tristan_synthetic show <каталог>
python3 -B -m scripts.tristan_synthetic preview <каталог> --indices 0
# Прочитайте BEFORE/AFTER и полные источники. Только затем:
python3 -B -m scripts.tristan_synthetic confirm <каталог> --indices 0 --preview-digest <digest-preview> --confirm-synthetic-memory
python3 -B -m scripts.tristan_synthetic show <каталог>
```

Альтернатива до confirm — `cancel <каталог>`. `import <каталог> <response-json>` принимает полный envelope только с правильной привязкой; старые benchmark-ответы не совместимы. Для машинного чтения `show/preview --json`; обычный review — читаемый текст, индексы с 0. Нет операций означает отсутствие кандидата, не доказательство полноты анализа.

Практический 2–3-минутный review: сравнить статус доступа с `Доступ.txt`; убедиться, что «права ещё не проверены» не превратилось в разрешение работы; выбрать только индекс 0, проверить, что инструкция и обязанность координатора буквально остались прежними; подтвердить preview, открыть новой командой show и проверить версию 2. CLI остаётся для инженерной пробы; обычный browser review описан ниже. Подключения к текущему context desk нет. Новый платный partial-запрос запрещён после уже выполненного одного запроса этого кейса.

## Бюджет и отказы

Общий дополнительный лимит **20 ₽** включает исходный benchmark **5,0888 ₽**. Он не возобновляется при новой сессии или ветке. Новый единственный journal `bridge-ledger.json` находится рядом с исходным benchmark; старые журналы только читаются. Старый guard с 90 ₽ не меняется и не вызывается: его накопленная оценка около **90,2783 ₽** уже выше guard. Счётчики ведутся в микрорублях, с консервативным округлением исторических float.

Предрезерв = UTF-8 bytes запроса × 0,0003 ₽ + 4096 × 0,0005 ₽. Один глобальный file lock удерживается до физического окончания запроса; повтор одного кейса запрещён. До чтения ключа и сети резерв атомарно записывается как unknown. Тайм-аут, HTTP error, отсутствие/невалидный usage, превышение резерва, авария или неопределённость записи удерживают резерв и блокируют последующие вызовы. Не удаляйте journal ради повтора. Complete/incomplete с достоверным usage могут быть учтены как оплаченный запрос, но неполный/невалидный кандидат всё равно отвергается. Локальная оценка не подтверждает списание.

Тариф проверен 12.11.2026: [Yandex AI Studio pricing](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing). Input 0,3 ₽/1000, output 0,5 ₽/1000 с НДС; reasoning входит в output и второй раз не считается. Скидки cache не используются для уменьшения безопасной оценки.

## Браузерный review — веха 13.11.2026

Отдельный сервер `scripts.tristan_synthetic_review` обслуживает только свою синтетическую сессию на `127.0.0.1`; порт 8796 запрещён. Он не импортирует sender или сервер/конфиг Gaia. HTTP-маршрутов отправки, загрузки файлов, произвольного текста, providers и реального store нет. Новый default demo создаёт отдельную temporary память только из pinned fixture:

```bash
python3 -B -m scripts.tristan_synthetic_review
```

Откройте выданный localhost URL. Дальше JSON и terminal digest не требуются. Слева — принятая память, в центре — изменения с «было / предложено / буквальное основание» и названием источника, справа — полные выбранные источники. «Показать основание» выделяет дословную цитату и переводит к ней. Действия остаются доступны при прокрутке. Индивидуальное «Исключить» и снятие флажка меняют только локальный выбор.

Все флажки изначально сняты. «Посмотреть итог» показывает полный собранный текст и число выбранных операций; переход к итогу виден сразу. Только после отдельного флажка «Я проверил итог…» доступна кнопка подтверждения. Digest обрабатывается приложением: непрозрачный одноразовый preview ticket связан с исходным пакетом, текущим view/candidate/version, выбором и computed after. При confirm сервер повторно валидирует состояние и вызывает неизменённый bridge confirm с его digest. Любая смена выбора сбрасывает preview и флажок; поздний preview/refresh не восстанавливает устаревшее состояние. Неизменённые фрагменты сохраняются буквально, смысл не аттестуется автоматически.

«Закрыть без принятия» отменяет проход без новой версии. После confirm/reload видны сохранённая версия, принятые/непринятые операции и закрытый проход. Повторный confirm запрещён. При empty response нет кнопки принятия и нет обещания полноты. Incomplete даёт понятный отказ без кандидата/автоповтора. `--demo unsupported`, `--demo incomplete`, `--demo conflict` — явно помеченные offline-сценарии; conflict остаётся только заранее известным ограничением registry, не общим семантическим детектором.

Для replay прежнего настоящего bound ответа:

```bash
python3 -B -m scripts.tristan_synthetic_review --replay-session <исходная-синтетическая-сессия>
```

Исходная сессия проверяется read-only. Неизменённые packet/request_id/base_version/digest и response копируются в **новую** temporary fixture memory версии1. Старый принятый store не переоткрывается и не меняется. UI явно обозначает replay; новых model/API-вызовов нет. `--session <каталог>` открывает уже существующую валидную синтетическую bridge-сессию, в том числе закрытую, без произвольных документов. Исчезнувший/невалидный временный каталог безопасно отклоняется.

Защита UI: per-server случайный HttpOnly/SameSite=Strict cookie, точный loopback Host и Origin для POST, запрет cross-site API, закрытая схема payload, ограниченный размер JSON, no-store/nosniff, CSP без inline script/style с frame-ancestors none, без CORS и content/access logs. Модельные строки выводятся через textContent, не HTML. Одновременно работающие вкладки/CLI учитываются version/view/preview gates; неизвестные/изменённые данные отклоняются, ошибки не выводят пути и сырые ответы. Клиент не передаёт after или preview_digest: этих полей в API нет. view_digest сверяется с текущим серверным состоянием; preview ticket и computed after хранятся на сервере.

Альтернатива до confirm — закрыть без принятия и убедиться, что осталась версия1. Никакая кнопка не вызывает модель или не меняет настоящую Gaia.

## Связанное синтетическое пространство Gaia — веха 13.11.2026

Следующий практический разрыв закрыт отдельно: прежний review сохранял результат в собственный bridge JSON-store, а рабочая память Gaia и её история оставались вне цикла. Новый **явно запускаемый** `scripts.tristan_gaia_trial` использует настоящие `ContextDesk`, `ProvenanceStore` и `AddressedMemoryPilot` в новой закрытой временной папке с искусственными данными. Он не переключает рабочую версию Gaia, не встраивает внешний provider и не подключает настоящий проект. Обычный запуск Gaia и прежнего review не меняются: workspace endpoints отключены по умолчанию (`make_server(..., workspace=False)`).

```bash
python3 -B -m scripts.tristan_gaia_trial
```

Откройте выданный `/workspace`. Слева видна текущая память, в центре — полные новые письма и задача, справа — история принятой памяти из того же ContextDesk. Начальная версия1 — контролируемая синтетическая fixture, созданная при bootstrap, а не автоматически принятый ответ модели. Кнопка открытия ответа явно создаёт/восстанавливает один локальный проход и проверяет кандидат. В review можно выбрать часть операций, проверить полный итог и отдельно подтвердить или отменить. Ссылка «Рабочая память и история Gaia» возвращает в то же пространство: после принятия видны версия2, выбранный итог и обе исторические версии. Невыбранные изменения не принимаются; повтор не создаёт новый проход или версию.

Для прежнего настоящего synthetic ответа используется `--replay-session <исходная-bridge-сессия>`; исходный store остаётся read-only, сетевого вызова нет. Без этого параметра UI явно обозначает учебный ответ. Поддержан также `--demo unsupported`: пустой кандидат закрывает проход без новой принятой версии. Known conflict/неполный или неверно связанный remote response не импортируются; общий семантический detector не появился.

После остановки можно продолжить **тот же** synthetic store:

```bash
python3 -B -m scripts.tristan_gaia_trial --resume <каталог-из-сообщения-запуска>
```

Принимаются только собственные temporary каталоги с marker, pinned packet и валидным изолированным содержимым; symlinks/реальные корни/чужие profiles не допускаются. Профиль и runtime config строятся только с путями внутри нового trial, пользовательский config не читается/не переписывается. Нет свободного выбора проекта, загрузки своего файла, HTTP analyze/send/provider/general desk API. Даже локальная модель не вызывается. Порт8796 запрещён. `flock` удерживает одного писателя на весь lifetime; второй `--resume` отклоняется. При остановке сервер ждёт текущие HTTP-записи до освобождения lease. Никакие чужие процессы не завершаются.

### Контракт локального адаптера

1. Сначала неизменённый `bridge.reply` проверяет полный исходный Responses envelope, **remote request_id/base_version/packet_digest** и операции с буквальными цитатами; legacy benchmark JSON без этих полей не переоборачивается.
2. Gaia создаёт собственный addressed request с собственным ID и оболочкой/номерами материалов. До импорта адаптер сверяет буквально прежнюю память, задачу и все полные тексты/версии локальных источников с pinned remote packet. Masking/storage guards не ослаблены: если преобразование меняет нужный текст, импорт не проходит.
3. `binding.json` в приватном synthetic trial фиксирует remote ID/digest/base_version ↔ local ID/local packet digest. Перевод оболочки выполняется **после** проверки исходной привязки и точного содержимого. Новые ID не дописываются за модель; произвольное rebinding не предоставлено. Это ограниченный adapter, не разрешение раскрытия или новая production architecture.
4. Локальный кандидат проходит штатный `AddressedMemoryPilot.propose`. Preview/confirm используют штатные `selection`/`decide`, source/version/hash checks и атомарную историю Gaia. Весь текущий кандидат дополнительно связан с server-side preview ticket. До confirm accepted memory не меняется.
5. После прерывания между prepare/import восстанавливается тот же local request, а не создаётся второй. После рестарта с предложением оно остаётся непринятым; volatile preview ticket утрачен и требует нового просмотра. Confirm/cancel переживают restart как закрытые состояния. Смена источников/пакета/версии/candidate/binding отвергается. Принятая память и исторические тексты проверяются на ожидаемый synthetic результат.

UI использует тот же защищённый same-origin server и review-компоненты. Дополнительные `/workspace`, `/workspace.js`, `/api/workspace` и `/api/prepare` доступны только в explicit workspace mode; default review отвечает404 на них. JSON/digest по-прежнему не нужен человеку. Binding, trial manifest и все источники находятся вне Git/MemoryHub; в память проекта попадают только разрешённые code/docs/tests snapshots и безопасные метаданные вехи.
