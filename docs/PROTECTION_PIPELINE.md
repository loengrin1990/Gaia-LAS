# Детерминированный защитный контур

Новые файлы проходят путь: контролируемый приём → источник → извлечение → локальная детерминированная очистка → очищенное представление → временный адаптер → существующий сборщик пакета. Адаптер получает только очищенный текст; исходный текст и таблица псевдонимов ему недоступны.

Обязательные проверки: электронная почта, телефоны, URL и сетевые адреса, секреты и локальные словари рабочего пространства. Дополнительные правила включают документы, реквизиты и явные адреса. Совпадения адресов и словарные сущности помечаются как требующие проверки. Ошибка обязательной проверки блокирует передачу; ошибка дополнительной сохраняет результат со статусом, требующим проверки. Сам pipeline не разрешает экспорт (`export_allowed=false`); отдельное ограниченное исключение ручного копирования описано ниже.

Псевдонимы хранятся только в отдельной зоне соответствующего рабочего пространства. Они устойчивы внутри пространства и изолированы между пространствами. Безопасный отчёт содержит категории, количества, псевдонимы, безопасную позицию, статус, уверенность и версию правила — без исходных значений, текста, путей и имён файлов.

Правила имеют версию. Повторная очистка управляемого результата создаёт новую версию очищенного представления, не импортируя источник повторно; прежняя версия сохраняется. Повторная загрузка того же файла блокируется до временного адаптера. Локальные словари находятся в закрытой зоне соответствующего пространства и не выдаются API.

Этап 3.1 не включает локальную языковую модель, ручную проверку, автоматическое разрешение экспорта, этап 3.2 или этап 4.

## Локальная дополнительная проверка (этап 3.2)

После детерминированной очистки только её текст передаётся существующей локальной модели через loopback-маршрут. Успешный ответ принимается только как полный JSON-объект со статусом завершения и списком находок; пустой список допустим лишь в таком полном успешном ответе. Каждая находка проверяется по разрешённой категории, координатам внутри очищенного текста, уровню уверенности и безопасному коду основания. Проверка запускается явно и синхронно: до запуска версия имеет состояние «Проверка ещё не запускалась», затем сразу переходит либо в «Найдены сведения, требующие проверки», либо в «Проверка завершена: дополнительных сведений не найдено», либо в безопасное состояние «Автоматическая проверка не завершена. Проверьте очищенный текст вручную». Пустой, неполный, некорректный, слишком большой или недоступный ответ никогда не означает отсутствие сведений.

Закрытый локальный API проверки возвращает очищенный текст и координаты только своему рабочему пространству; безопасный API отчёта по-прежнему не возвращает текст. Пользователь может принять замену или оставить совпадение, затем явно подтверждает актуальную версию. При недостоверном автоматическом результате подтверждение остаётся доступно только как отдельное ручное решение и помечается как ручное, а не как успешная проверка Veil. Только явное подтверждение разрешает постановку существующего анализа. Подтверждение старой версии недействительно после новой очистки. Экспорт остаётся запрещённым.

После ручного подтверждения сохраняется тот же существующий путь: пользователь нажимает «Собрать проектный контекст», а compiler принимает актуальную подтверждённую версию и создаёт кандидаты. Повторное подтверждение не создаёт вторую задачу анализа. Veil предназначен для ПД: полных ФИО, email, телефонных номеров (в цифрах и в явно помеченной словесной записи), адресов, документов и идентификаторов. Коммерческие лимиты и иные сведения коммерческой тайны не входят в этот контракт; их корректное покрытие требует отдельного продуктового этапа с классификацией коммерческой чувствительности, а не скрытого расширения PII-маскирования.

Пользователь также может изменить категорию кандидата или добавить его координатный фрагмент в словарь своего пространства. Добавление обновляет локальный словарь и запускает новую очистку управляемого результата без повторной загрузки источника.

Когда пользовательское действие создаёт новую очищенную версию, Gaia создаёт для неё новое состояние проверки до возврата успешного ответа. В нём сохраняется история решений прежней версии, но не её подтверждение; локальная проверка выполняется заново для актуального очищенного текста. Это не допускает расхождения, при котором список материалов уже указывает на новую версию, а проверка ещё отсутствует.

Каждая находка привязана к конкретной версии очищенного текста, её координатам и одностороннему отпечатку ожидаемого фрагмента. Повторное решение по находке, устаревшие координаты и совпадение с уже созданным псевдонимом отклоняются без изменения текста. Повторная очистка сначала строит все непересекающиеся замены по неизменному исходному извлечению, затем применяет их с конца строки: созданный псевдоним не может стать входом следующего правила.

Словарное значение применяется только как целый самостоятельный фрагмент, а не как часть обычного слова, названия или номера. Локальная модель также не может предложить часть слова либо диапазон, пересекающий сформированный псевдоним. После каждого сохранённого решения Gaia показывает число оставшихся находок; когда их нет, версия готова к подтверждению. Решения разрешены только для завершённой проверки с необработанными находками; подтверждение — только для актуальной версии в состоянии «Готово к подтверждению».

Подтверждённая актуальная очищенная версия может быть передана только локальному [компилятору проектного контекста](CONTEXT_COMPILER.md); автоматический экспорт по-прежнему запрещён. Исключение ручного копирования пилота описано ниже.

Пользовательский переход от добавления к проверке описан в [интерфейсе Gaia](USER_INTERFACE.md). Экран не раскрывает исходный источник, контрольные суммы или таблицу псевдонимов.

## Исключение пилота: ручное копирование проверенного пакета

Решение владельца от 05.10.2026: разрешён цикл «просмотр полного пакета → ручное копирование в выбранный сильный чат → возврат структурированного ответа → проверка и подтверждение памяти», без внешних API.

Исключение действует только в `context_desk`, для конкретного подготовленного прохода. Пакет содержит инструкцию, задачу, прежнюю принятую память и полные извлечённые тексты выбранных материалов в пределах установленного лимита. Он не включает исходные бинарные файлы, изображения или неизвлечённые части документов. Текст не обрезается молча.

Перед копированием пользователь просматривает полный текст, отдельно подтверждает право передачи задачи/названия проекта, каждого материала с его источниками и всей принятой памяти с её источниками в выбранный чат. По умолчанию разрешение неизвестно. Ограниченные материалы и материалы без установленного разрешения не допускаются; маскирование не снимает ограничений. Утверждение пользователя — контролируемое разрешение этого ручного действия, не автоматическая классификация содержимого и не изменение handling исходников.

Сервер повторно проверяет текущую версию памяти и доступность/целостность выбранных источников, сравнивает хеш всего просмотренного пакета и требует подтверждений всего набора. Разрешение записывается локально с хешем, временем и выбранными подтверждениями, без текста в журнале. Новая версия пакета требует новой проверки. Автоматической отправки нет: Gaia выдаёт текст браузеру для буфера обмена, пользователь выбирает чат и сам вставляет пакет.

Общий `export_allowed` protection pipeline остаётся `false`; исключение не создаёт PB-0 external eligibility, не разрешает API-вызовы и не меняет OC routing. Ответ чата привязан к проходу, проходит проверку структуры и буквальных цитат и становится только предложением. Принятая память меняется после отдельного подтверждения.
